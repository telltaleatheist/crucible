# crucible `tts` env — BOTH narrator engines on mlx-darwin.
#
# Installed by `crucible install tts --narrator-engine <higgs-v3|orpheus>` into
# ~/.crucible/envs/tts/ — one directory, whichever engine is named, because on
# the Mac the two genuinely do share a stack. `jobenv.tts_env()` resolves both
# names to this one env and both `crucible doctor` rows carry the same path, so
# that the sharing is visible rather than implied.
#
# Read `higgs-v3-cuda-linux.txt`'s header for why narrator is pinned by a git
# sha, why only narrator's own exact pins are restated here, and why this is not
# yet a resolved set.
#
# WHY ONE ENV HERE AND TWO ON CUDA-LINUX
# --------------------------------------
# narrator's `narrator-mlx` extra was renamed from `orpheus-mlx` on 2026-09-05,
# when Higgs v3 gained an in-process MLX backend, and narrator's own comment
# explains the rename exactly: "the group is no longer Orpheus's, it is THE
# MAC's". Higgs v3 on the Mac shares every one of these pins and adds none —
# `mlx_audio.tts.models.higgs_audio_v3` and `mlx_audio.codec.models.higgs_audio`
# are both in mlx-audio 0.4.8, they load the official
# `bosonai/higgs-audio-v3-tts-4b` safetensors with no conversion step, and the
# codec comes out of the same shards. There is no second model download and no
# mlx-community repo in the picture.
#
# The Mac also runs the engines IN PROCESS rather than starting a server
# underneath narrator, which is why nothing here corresponds to `vllm-omni`.
#
# TWO OF THESE PINS ARE EXACT FOR MEASURED REASONS, IN NARRATOR'S OWN WORDS
# ------------------------------------------------------------------------
#   mlx-lm==0.31.3    the batched fast path is version-PINNED, not
#                     feature-detected (mlx_fastpath refuses below it); 0.31.3 is
#                     where `GenerationBatch` exists.
#   mlx-audio==0.4.8  0.5.1 CANNOT RENDER ORPHEUS — `mlx_audio/lm/generate.py`'s
#                     `_eos_ids` does `set(tokenizer.eos_token_ids)` on an int
#                     (128009) under transformers 5.x and raises TypeError on
#                     EVERY generate. 0.3.x drags mlx-lm below the fast-path pin.
#                     0.4.8 is the one version that works, and it only requires
#                     mlx>=0.31.1, so it coexists with narrator's mlx floor.
#
# narrator's remaining Mac requirements are RANGES rather than pins — `mlx>=0.32.0`
# (for `mx.new_thread_unsafe_stream`, which decode overlap needs; below it the
# engine degrades to serial decode, loudly), `torch>=2.5`, `transformers>=4.57`
# and `numpy>=2,<3`. They stay narrator's: a range is a deliberate statement
# about what the code tolerates, and turning it into a number here would be
# Crucible inventing a pin nobody measured. pip resolves them from narrator's own
# metadata.
