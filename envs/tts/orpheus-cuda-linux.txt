# crucible `tts` env — narrator's `orpheus` engine on cuda-linux.
#
# Installed by `crucible install tts --narrator-engine orpheus` into
# ~/.crucible/envs/tts-orpheus/. Read `higgs-v3-cuda-linux.txt`'s header first:
# why there are two envs here, why narrator is pinned by a git sha, why only
# narrator's own exact pins are restated, and why this is not yet a resolved set
# are all the same answers and are written out there.
#
# `vllm==0.7.3` IS THE WHOLE REASON THIS ENV EXISTS SEPARATELY
# -----------------------------------------------------------
# It is the last version whose V0 engine takes per-request logits processors —
# and a per-request logits processor is what the Orpheus EOS boost *is*. Above
# it, V1 has no such hook and the boost silently stops applying: the model keeps
# generating past where it should have stopped, and nothing in the output says
# the lever was ignored. narrator's own pyproject calls it "a hard pin, not a
# floor" and its spawn environment sets `VLLM_USE_V1=0` for the same reason.
#
# That pin is why `crucible install tts` REQUIRES --narrator-engine on this
# backend: 0.7.3 and 0.28.0 cannot be the same env, and the command may not pick
# for you.
#
# torch 2.5.1+cu121 and numpy 1.26.4 travel with it: that torch's ABI needs
# numpy 1.x, and resolving numpy upward drags torch and vLLM with it and breaks
# CUDA-graph capture — which is the whole point of running Orpheus on Linux
# rather than on Windows in the first place (BookForge's CLAUDE.md: ~15 s per
# sentence with `enforce_eager`, ~2-3 s with graphs).
#
# NB narrator's own comment on these numbers: "vLLM and torch are deliberately
# NOT installed by pip in practice — the envs were built by hand with the
# CUDA-matched wheels — so these pins document and VERIFY what must already be
# there rather than fetching it." A `crucible install tts --narrator-engine
# orpheus` on a clean host will therefore pull the generic PyPI wheels, and the
# first person to do it should check that `torch.cuda.is_available()` before
# concluding the env is good. `crucible doctor` checks the versions; it cannot
# check the CUDA build they were compiled against.
