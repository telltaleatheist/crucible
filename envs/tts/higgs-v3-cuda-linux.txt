# crucible `tts` env — narrator's `higgs-v3` engine on cuda-linux.
#
# Installed by `crucible install tts --narrator-engine higgs-v3` into
# ~/.crucible/envs/tts-higgs-v3/ as a venv built from the server's own
# interpreter. The server process never imports any of this: narrator is started
# as a subprocess of this venv's python (`python -m narrator.serve`, with
# NARRATOR_ENGINE=higgs-v3).
#
# WHY THERE IS AN ENV PER NARRATOR ENGINE HERE AND NOT PER BACKEND
# ----------------------------------------------------------------
# `llm` has one env per host. `tts` on cuda-linux has two, and the reason is in
# narrator's dependency matrix rather than in Crucible's design: Orpheus needs
# `vllm==0.7.3` and Higgs v3 needs `vllm==0.28.0` plus `vllm-omni==0.28.0`
# against a much later torch. narrator's own pyproject.toml says so in as many
# words — "Installing any two into one env resolves torch twice and breaks
# whichever loses" — and its extras are mutually exclusive for exactly that
# reason. So this file is the `higgs-v3-server` extra and
# `orpheus-cuda-linux.txt` is the `orpheus` one. On mlx-darwin the two genuinely
# do share an env, and there is one recipe there.
#
# NARRATOR IS PINNED BY GIT SHA, AND THAT IS AN OWED RULING RATHER THAN A HACK
# ---------------------------------------------------------------------------
# narrator is not on PyPI. It is `python/narrator` in the BookForge repo: a
# proper installable package whose `engine/` and `serve/` know nothing about
# audiobooks, but whose `compat/` and `assemble/` do, and which is versioned with
# the app. PHASE3-TTS.md section 4: **extracting narrator into its own repo is an
# owed ruling for Owen**, and until he makes it this pin is the honest
# arrangement rather than a workaround — a server is then never surprised by a
# commit somebody pushed to `main` this afternoon.
#
# `crucible doctor` verifies it against the COMMIT pip recorded (PEP 610's
# direct_url.json), not against narrator's declared version, which does not move
# when the sha does.
#
# WHY ONLY FOUR REQUIREMENTS
# --------------------------
# narrator declares its own base dependencies, and it declares them as RANGES on
# purpose: numpy is `>=1.26.4,<3` in the base and an exact number inside each
# env's extra, because pinning 1.26.4 at the base would have `pip install -e
# python/` downgrade numpy underneath a torch built against 2.x. Restating those
# ranges here as exact versions would mean Crucible pinning numbers it did not
# choose, cannot verify from this machine, and would have to re-guess on every
# narrator bump. So this recipe carries the direct reference and the three pins
# narrator's `higgs-v3-server` extra states EXACTLY — every one of them read off
# a working WSL env by narrator's own authors rather than picked — and lets pip
# resolve the rest from narrator's metadata.
#
# THIS FILE IS NOT YET A RESOLVED SET, AND THAT IS DELIBERATE
# ----------------------------------------------------------
# The same notice `envs/asr/cuda-linux.txt` carries, for the same reason: it was
# written on a machine with no free accelerator (the 3090 Ti was on an overnight
# fine-tune) and nothing here has been installed anywhere. `crucible doctor`
# calls the env NOT READY if any pin is absent or at another version, so the
# first person to run the install finds out at once whether pip agreed. When it
# does, regenerate this file from the truth and delete this notice:
#
#     ~/.crucible/envs/tts-higgs-v3/bin/python -m pip freeze
#
# TWO SITE-PACKAGES PATCHES ARE NOT EXPRESSIBLE HERE AND MUST BE RE-APPLIED
# AFTER ANY UPGRADE OF THESE PINS:
#
#   work/patch_vllm.py       without it every voice-clone request is HTTP 400
#   work/patch_tail_trim.py  without it every chunk ends in ~240 ms of audible
#                            garbage
#
# pip cannot express a patch to somebody else's installed package. `crucible
# doctor` reports both by name under `narrator_patches`, so an env that is
# "ready" by its pins alone is not mistaken for one that will render correctly.

narrator[higgs-v3-server] @ git+https://github.com/telltaleatheist/bookforge@770415db591e0af2cc650cf8c889224972e8906d#subdirectory=python
