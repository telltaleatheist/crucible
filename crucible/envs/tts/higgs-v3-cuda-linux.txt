# crucible `tts` env - narrator's `higgs-v3` engine on cuda-linux, SGLang-Omni.
#
# Installed by `crucible install tts --narrator-engine higgs-v3` into
# ~/.crucible/envs/tts-higgs-v3/. The server process never imports any of this:
# narrator is started as a subprocess of this env's python
# (`python -m narrator.serve`, with NARRATOR_ENGINE=higgs-v3).
#
# ---------------------------------------------------------------------------
# THIS RECIPE SERVED vllm-omni UNTIL 2026-09-15. IT DOES NOT ANY MORE.
# ---------------------------------------------------------------------------
#
# Owen, 2026-09-15: "we dont use vllm-omni. we use sglang. vllm-omni doesnt work
# for higgs."
#
# That is a ruling about CORRECTNESS, not a preference between two working
# stacks, and the measurement behind it is the training side's of 2026-09-05 -
# the same 50 packed chunks of *Working Towards the Fuhrer*, the same merged
# checkpoint (ckpt-1080), the same sampling, one seed, scored by whisper
# coverage / skipped words / insertion rate / early stop plus 3 s ECAPA windows
# for mid-chunk voice switches (orpheus-finetune/HIGGS_FIELD_NOTES.md 4n):
#
#     engine, in flight        early stops  damaged/50  switches  chars/min
#     vllm-omni 0.28.0, 1           0            5          0        1,064
#     vllm-omni 0.28.0, 16          4           13          6       10,752
#     SGLang-Omni 0.1.4, 16         0            5          0       26,666
#
# vllm-omni's damage is its BATCHED TALKER and not the model or the text: the
# same build at width 1 is clean, and the corruption lands on the NEWEST batch
# row (the request that prefills while others decode, which vLLM's condense
# moves when an earlier row retires). The truncations Owen heard, the gibberish
# and the sustained voice switches are all that one defect. BookForge's own
# catalog flipped to `stack: "sglang-omni"` on 2026-09-06 on these numbers;
# Crucible rendered on the other stack for nine days because this file installed
# it, which is the divergence the 2026-09-15 narrator-seam audit found.
#
# THE vllm-omni RECIPE IS REPLACED RATHER THAN KEPT BESIDE THIS ONE. A second
# recipe that serves Higgs on vllm-omni is a supported way to render a damaged
# book, and Crucible does not keep one. Nothing is lost: BookForge's catalog
# keeps the vllm-omni knobs beside its sglang block so a flip is one word,
# narrator keeps both backends and both launchers, and this file's own history
# holds the resolved vllm-omni set.
#
# ---------------------------------------------------------------------------
# WHY THERE IS AN ENV PER NARRATOR ENGINE HERE AND NOT PER BACKEND
# ---------------------------------------------------------------------------
# `llm` has one env per host. `tts` on cuda-linux is named per narrator engine,
# because each engine pins its own serving stack against its own torch.
# narrator's own pyproject.toml says so in as many words - "Installing any two
# into one env resolves torch twice and breaks whichever loses" - and its extras
# are mutually exclusive for exactly that reason. This file is the
# `higgs-v3-sgl` extra. On mlx-darwin the engines share an env and there is one
# recipe there.
#
# ---------------------------------------------------------------------------
# THIS ENV IS PYTHON 3.12, AND THAT IS NOT A DETAIL
# ---------------------------------------------------------------------------
# sglang-omni 0.1.4 pulls torch 2.13.0+cu130 and flashinfer against a 3.12
# interpreter. The vllm-omni env was 3.11, and `jobenv.install_env` built every
# env with `sys.executable -m venv` - the SERVER'S interpreter, which on
# owens-pc is python 3.11.16. So this recipe cannot be built by the machinery
# that built the last one, and `EnvSpec.python_version` is what carries the
# requirement: an install that cannot find a 3.12 REFUSES BY NAME rather than
# building a 3.11 env that pip then fails to fill.
#
# BookForge builds the same stack as a SEPARATE CONDA ENV (`sglomni`) for the
# same reason, and its installer's first line is "Never touches higgs3".
#
# ---------------------------------------------------------------------------
# TWO THINGS pip CANNOT EXPRESS, AND NEITHER IS A PATCH
# ---------------------------------------------------------------------------
#  1. flashinfer JIT-builds its attention kernels with the CUDA 13 nvcc that
#     ships INSIDE the pip wheel, and only once that directory looks like a
#     toolkit: `lib64 -> lib` and `libcudart.so -> libcudart.so.13` inside
#     <env>/lib/python3.12/site-packages/nvidia/cu13, which is also what
#     CUDA_HOME must point at. `serve_higgs_sgl.sh` points at them;
#     `crucible/narratorpatches.py` creates and checks them, the same
#     after-pip-and-before-the-stamp discipline the vllm-omni patches had.
#  2. `flashinfer-jit-cache` is published on flashinfer's OWN per-CUDA index and
#     is on no PyPI, hence the `--extra-index-url` below. Without it the server
#     still starts and compiles its kernels at every cold start instead.
#
# THERE ARE NO SITE-PACKAGES PATCHES ON THIS STACK. The two the vllm-omni env
# needed (the negative-token-id fix and the sentinel filter) are edits to
# vllm/vllm_omni. SGLang-Omni has its own stage processor and needs neither,
# which is a real difference between the stacks rather than an omission - and it
# is why `crucible doctor` reports no patch rows here.
#
# ---------------------------------------------------------------------------
# A RESOLVED SET, READ FROM THE ENV THAT ACTUALLY WORKS
# ---------------------------------------------------------------------------
# What follows is `pip list --format=freeze` from the `sglomni` conda env on
# owens-pc (WSL2, Ubuntu, python 3.12.14) on 2026-09-15 - the env every night-3
# measurement above was taken against - with `pip`, `setuptools` and `wheel`
# dropped (the venv brings its own and `install_env` upgrades them) and
# narrator's direct reference added. Owen's instruction was "look at the old
# bookforge config. mirror it. it should be exact", and this is that env's own
# answer rather than a guess at what SGLang needs.
#
# `uv` IS ON THE LIST ON PURPOSE. BookForge's installer pip-installs uv into the
# env and resolves sglang-omni with `uv pip install --prerelease=allow`, because
# that dependency set does not resolve under plain pip's strategy. A FULLY
# PINNED set needs no resolution strategy, so plain pip can install this file -
# but uv is in the working env and dropping it would make this list something
# other than what was measured.
#
# NARRATOR'S PIN CARRIES THE LAUNCHER. It must be at or after bookforge
# edca6c22, which is the commit that ships `serve_higgs_sgl.sh` as package data.
# Before it, `sgl_served` had only the operator override and refused to start
# without a path into a BookForge checkout - so an older pin here is an env that
# installs cleanly and cannot serve.

# flashinfer publishes per-CUDA wheels on its own index and none on PyPI. The
# cu130 build is the one that matches torch 2.13.0+cu130 above.
--extra-index-url https://flashinfer.ai/whl/cu130/
