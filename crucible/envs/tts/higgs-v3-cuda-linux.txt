# crucible `tts` env — narrator's `higgs-v3` engine on cuda-linux.
#
# Installed by `crucible install tts --narrator-engine higgs-v3` into
# ~/.crucible/envs/tts-higgs-v3/ as a venv built from the server's own
# interpreter. The server process never imports any of this: narrator is started
# as a subprocess of this venv's python (`python -m narrator.serve`, with
# NARRATOR_ENGINE=higgs-v3).
#
# WHY THERE IS AN ENV PER NARRATOR ENGINE HERE AND NOT PER BACKEND
# ----------------------------------------------------------------
# `llm` has one env per host. `tts` on cuda-linux is named per narrator engine,
# and the reason is in narrator's dependency matrix rather than in Crucible's
# design: each engine pins its own serving stack against its own torch — this
# one needs `vllm==0.28.0` plus `vllm-omni==0.28.0`. narrator's own
# pyproject.toml says so in as many words — "Installing any two into one env
# resolves torch twice and breaks whichever loses" — and its extras are
# mutually exclusive for exactly that reason. So this file is the
# `higgs-v3-server` extra. On mlx-darwin the engines share an env, and there is
# one recipe there.
#
# SINCE 2026-09-14 THIS IS THE ONLY cuda-linux tts RECIPE. Owen's ruling that
# day removed `orpheus` from the engines Crucible names (see
# `crucible/voices.py`'s `NARRATOR_ENGINE_SAMPLING`), and
# `envs/tts/orpheus-cuda-linux.txt` went with it. The per-engine NAMING stays,
# because the next engine needs its own file here and not an edit to this one.
#
# NARRATOR IS PINNED BY GIT SHA, AND THAT IS AN OWED RULING RATHER THAN A HACK
# ---------------------------------------------------------------------------
# narrator is not on PyPI. It is `python/narrator` in the BookForge repo: a
# proper installable package whose `engine/` and `serve/` know nothing about
# audiobooks, but whose `compat/` and `assemble/` do, and which is versioned with
# the app. PHASE3-TTS.md section 4: **extracting narrator into its own repo is an
# owed ruling for Owen**, and until he makes it this pin is the honest
# arrangement rather than a workaround — a server is then never surprised by a
# commit somebody pushed to `main` this afternoon.
#
# `crucible doctor` verifies it against the COMMIT pip recorded (PEP 610's
# direct_url.json), not against narrator's declared version, which does not move
# when the sha does.
#
# WHY THE CHOSEN SET WAS ONLY FOUR REQUIREMENTS (history; the resolved set below supersedes it)
# --------------------------
# narrator declares its own base dependencies, and it declares them as RANGES on
# purpose: numpy is `>=1.26.4,<3` in the base and an exact number inside each
# env's extra, because pinning 1.26.4 at the base would have `pip install -e
# python/` downgrade numpy underneath a torch built against 2.x. Restating those
# ranges here as exact versions would mean Crucible pinning numbers it did not
# choose, cannot verify from this machine, and would have to re-guess on every
# narrator bump. So this recipe carries the direct reference and the three pins
# narrator's `higgs-v3-server` extra states EXACTLY — every one of them read off
# a working WSL env by narrator's own authors rather than picked — and lets pip
# resolve the rest from narrator's metadata.
#
# A RESOLVED SET, read from a real install
# ----------------------------------------
# What follows is `pip freeze` from `crucible install tts --narrator-engine higgs-v3` on
# Owen's PC (WSL2, Ubuntu, python 3.11.16) on 2026-09-13: every package pip
# resolved, at the version it resolved. The earlier notice that this file was a
# CHOSEN set and not a measured one is discharged by that install; `crucible
# doctor` checks the env against exactly these lines.
#
# TWO SITE-PACKAGES PATCHES ARE NOT EXPRESSIBLE HERE, AND INSTALLING THIS FILE
# RE-APPLIES THEM:
#
#   patches/patch_vllm.py    without it every voice-clone request is HTTP 400
#   patches/patch_sentinel_filter.py
#                            without it every chunk ends in ~240 ms of audible
#                            garbage AND narrator's sentinel proof refuses the
#                            load, because the record-per-invocation report it
#                            reads is written by the patched file
#
# pip cannot express a patch to somebody else's installed package — worse, pip
# UNDOES one, by writing the distribution's own file over the edit. So
# `jobenv.install_env` runs both appliers after pip and before it stamps the
# env, and `crucible/narratorpatches.py` re-checks the result and refuses the
# install if the markers are not there. `crucible doctor` reports both by name
# under `narrator_patches` for an env installed some other way.
#
# THIS PARAGRAPH USED TO SAY "MUST BE RE-APPLIED AFTER ANY UPGRADE OF THESE
# PINS" and name nobody who would. MEASURED 2026-09-15: `crucible install tts
# --narrator-engine higgs-v3 --build --force` at 07:34 restored both files
# pristine, and every Higgs load from 07:46 failed at narrator's sentinel proof
# with a 0-byte report — from the same pins, the same recipe and the same
# narrator sha that had rendered at 07:23. It also named `work/patch_tail_trim.py`,
# retired 2026-09-05 and superseded by the sentinel filter.
