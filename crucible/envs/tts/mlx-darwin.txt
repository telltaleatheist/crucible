# crucible `tts` env — EVERY narrator engine on mlx-darwin.
#
# Installed by `crucible install tts --narrator-engine <engine>` into
# ~/.crucible/envs/tts/ — one directory, whichever engine is named, because on
# the Mac they genuinely do share a stack. `jobenv.tts_env()` resolves every
# name to this one env and every `crucible doctor` row carries the same path,
# so that the sharing is visible rather than implied. Since Owen's ruling of
# 2026-09-14 there is exactly one such engine, `higgs-v3`; the recipe stays
# named for the BACKEND because that is what it is named for here.
#
# Read `higgs-v3-cuda-linux.txt`'s header for why narrator is pinned by a git
# sha, why only narrator's own exact pins are restated here, and why this is not
# yet a resolved set.
#
# WHY ONE ENV HERE AND ONE PER ENGINE ON CUDA-LINUX
# -------------------------------------------------
# narrator's `narrator-mlx` extra is named for the MAC rather than for an
# engine, in narrator's own words on 2026-09-05, when Higgs v3 gained an
# in-process MLX backend: "the group is no longer [one engine]'s, it is THE
# MAC's". Higgs v3 on the Mac shares every one of these pins and adds none —
# `mlx_audio.tts.models.higgs_audio_v3` and `mlx_audio.codec.models.higgs_audio`
# are both in mlx-audio 0.4.8, they load the official
# `bosonai/higgs-audio-v3-tts-4b` safetensors with no conversion step, and the
# codec comes out of the same shards. There is no second model download and no
# mlx-community repo in the picture.
#
# The Mac also runs the engines IN PROCESS rather than starting a server
# underneath narrator, which is why nothing here corresponds to `vllm-omni`.
#
# TWO OF THESE PINS ARE EXACT FOR MEASURED REASONS, IN NARRATOR'S OWN WORDS
# ------------------------------------------------------------------------
#   mlx-lm==0.31.3    the batched fast path is version-PINNED, not
#                     feature-detected (mlx_fastpath refuses below it); 0.31.3 is
#                     where `GenerationBatch` exists.
#   mlx-audio==0.4.8  0.5.1's `mlx_audio/lm/generate.py` `_eos_ids` does
#                     `set(tokenizer.eos_token_ids)` on an int (128009) under
#                     transformers 5.x and raises TypeError on EVERY generate.
#                     0.3.x drags mlx-lm below the fast-path pin. 0.4.8 is the
#                     one version that works, and it only requires mlx>=0.31.1,
#                     so it coexists with narrator's mlx floor.
#                     PIN OWED A RE-MEASUREMENT. The failure above was measured
#                     on the engine Owen removed on 2026-09-14, and this file
#                     has never been re-run against 0.5.1 with `higgs-v3`
#                     alone. The number stays where the measurement put it —
#                     moving a pin on the strength of a deleted engine would be
#                     Crucible inventing a pin nobody measured — but whether
#                     0.4.8 is still the ceiling is an open question for the
#                     Mac, not a settled one.
#
# narrator's remaining Mac requirements are RANGES rather than pins — `mlx>=0.32.0`
# (for `mx.new_thread_unsafe_stream`, which decode overlap needs; below it the
# engine degrades to serial decode, loudly), `torch>=2.5`, `transformers>=4.57`
# and `numpy>=2,<3`. They stay narrator's: a range is a deliberate statement
# about what the code tolerates, and turning it into a number here would be
# Crucible inventing a pin nobody measured. pip resolves them from narrator's own
# metadata.

# THIS PIN IS A CAPABILITY, NOT JUST A VERSION. Crucible's take ladder sends a
# rung as `sampling` on every `generate_batch` item, and only a narrator
# carrying `narrator/engine/item_sampling.py` reads it; an older one drops the
# key in SILENCE and renders take 0. Measured 2026-09-15: this pin was
# 0eeb0267, one day too old, and two render jobs at take 0 and take 1 returned
# byte-identical audio. The refusal that now catches it (`sampling_not_wired`,
# off `itemSampling` on narrator's ready line) makes a stale pin loud rather
# than wrong -- but loud still means the ladder does not run, so re-resolve
# this to a bookforge commit at or after fbc235bf when bumping the env.
